# 개인정보와 배포

## 데이터 경로

CSV → 브라우저 UTF-8 파서 → 정규화·품질 감사 → 사용자의 명시적 적용 → 현재 origin의 IndexedDB.

웹 앱에는 CSV 업로드 API, 분석 서버, 외부 추적, 광고, 원격 폰트가 없습니다. UI에 표시하는 메모는 React 텍스트 노드이며 HTML로 해석하지 않습니다. JSON 복원은 버전·구조·수치·중복 ID를 검증합니다. CSV 내보내기는 스프레드시트 수식 시작 문자를 이스케이프합니다.

브라우저 저장소는 암호화·로그인·자동 동기화를 의미하지 않습니다. 공유 기기에서는 다른 사용자의 접근이 가능하고 브라우저 초기화·시크릿 모드·저장소 정리로 유실될 수 있습니다. JSON/CSV 백업도 개인 데이터이므로 안전한 개인 공간에 보관하세요.

Vite 개발 서버에서도 data/, reports/, docs/private/, CSV·Parquet·개인 JSON, 비공개 개발 지침과 Git/환경 파일의 HTTP 제공을 명시적으로 차단합니다. 개인 원본은 파일 선택으로만 브라우저에 가져오세요. 배포 서버는 dist만 제공해야 합니다.

전체 삭제는 앱의 IndexedDB 상태를 빈 상태로 교체하고 메모리의 개인 기록을 제거합니다. 이미 내려받은 백업과 브라우저 밖 원본은 별도로 관리해야 합니다. 서비스워커에는 정적 앱 자산만 캐시하며 개인 상태를 캐시하지 않습니다.

## 공개 배포 절차

현재 개발 저장소는 **비공개 유지**가 필수입니다. 기존 저장소의 visibility를 바꾸거나 `.git`/커밋 이력을 공개 저장소로 옮기지 마세요. 마스터 요구사항에는 민감한 개인 배경이 있으므로 `dist/`만 안전하다는 사실이 저장소 전체의 공개 허가를 뜻하지 않습니다.

```bash
npm run release:prepare
```

이 명령은 빌드·공개 산출물 검사 후 `release/public-code-<임의값>/`에 허용한 코드·일반 문서만 복사합니다. 기존 staging을 덮어쓰지 않습니다. `.git`, `data/`, `reports/`, `docs/private/`, 개인 지침, 환경값, 테스트 캡처는 제외합니다. 별도의 **새 공개 코드 전용 저장소**에 이 디렉터리의 파일만 새 Git 이력으로 올리세요.

1. 새 공개 저장소의 Settings → Pages → Source를 **GitHub Actions**로 설정합니다.
2. Actions에서 **Deploy public app**을 수동 실행합니다.
3. 워크플로는 공개 저장소인지 검사하고 `VITE_BASE_PATH=/<실제 저장소 이름>/`으로 빌드합니다.
4. 업로드하는 아티팩트는 `dist/`뿐입니다. `actions/deploy-pages`가 반환한 실제 URL과 동작을 확인한 후 배포 완료로 표시하세요.
5. 배포 뒤 `Live site browser verification` 작업이 실제 HTTPS 주소를 새 브라우저 컨텍스트로 엽니다. 데스크톱·모바일의 10개 화면, 합성 CSV·로컬 저장·바벨 선택·오프라인 실행을 검사하고 외부 요청이나 데이터 업로드가 있으면 실패합니다. 개인 CSV는 이 검사에 사용하지 않습니다.

기본 로컬 base는 `/hypertrophy-lab/`입니다. 루트/커스텀 도메인 배포는 `VITE_BASE_PATH=/ npm run build`로 생성합니다. 화면 이동은 해시 라우팅이므로 정적 호스팅의 새로고침 404를 피합니다. 각 base 변경 후 해당 경로와 오프라인 캐시를 실제 확인하세요.

GitHub 연동의 새 저장소 생성 권한과 기존 저장소 접근 권한은 다릅니다. 계정 소유자가 빈 공개 저장소를 만든 경우에는 먼저 해당 저장소의 접근·push 권한을 확인하세요. 연결이 선택한 저장소만 허용한다면 GitHub Settings → Applications → Installed GitHub Apps에서 Codex 연결을 Configure하고 새 공개 저장소를 추가합니다. 공개 배포에는 검사한 staging만 새 이력으로 올리며, 기존 비공개 저장소의 공개 전환으로 대체하지 마세요.

## 검사 범위

`npm run audit:public`은 dist 파일 허용 목록, 비공개 경로/표식, 알려진 로컬 개인 파일 이름, 추적된 민감 디렉터리를 검사합니다. 모든 PII를 자동으로 탐지하는 도구는 아니며 최종 앱 코드와 staging의 내용을 검토해야 합니다. 개인 데이터가 나중에 소스 상수·이미지·스크린샷에 들어가면 다시 감사를 수행하세요.

현재 Git 이력의 파일 경로도 검토해야 합니다. 비공개 개발 지침이 들어 있는 이력을 공개하지 않고 새 코드 전용 이력을 만드는 것이 필수입니다. 배포용 staging 자체에는 `.git`이 없습니다.
