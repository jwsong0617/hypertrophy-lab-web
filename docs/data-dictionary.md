# 데이터 사전과 재현 규칙

앱의 계산은 `src/domain/`에 있으며 개인 CSV는 브라우저에서만 읽습니다. CLI 분석은 원본을 읽기 전용으로 열고 `reports/private/`에 결과를 저장합니다.

| 원본/입력 | 정규화 | 집계 규칙 |
|---|---|---|
| Workout # | `sourceId`, `strong:<번호>` | 파일 이름과 무관한 세션 키. 재가져오기는 같은 세션을 교체 |
| Date | `date`, `startedAt` | 시간대 없는 `YYYY-MM-DD HH:mm:ss`는 Asia/Seoul. 명시적 Z/offset은 한국 날짜로 변환 |
| Exercise Name | 원래 이름 + 카탈로그 ID | 정확한 별칭으로 분류. 모르는 종목은 임의 추정하지 않음 |
| Set Order = 숫자 | `work` | 반복수 1 이상인 경우만 기본 본세트 |
| W / D / Rest Timer | `warmup` / `drop` / `rest` | 별도로 보관하고 기본 본세트·톤수에서 제외 |
| 시간·거리 운동 | `cardio` / `timed` | kg×반복수 및 근력 본세트에서 제외. 시간 기반 코어 운동은 timed |
| 알 수 없는 표식 | `unknown` | 보관·감사에 표시. 기본 본세트에서 제외 |
| Weight (kg) | `weight: number \| null` | 공란은 null, 실제 0은 0. 음수·비유한 값·상한 밖 수치 거부 |
| Reps | `reps: integer \| null` | 공란·0은 수행 본세트로 집계하지 않음 |
| RPE / RIR | 각각 nullable | 미입력은 추정하지 않음. 가져온 RPE로 누락 RIR를 자동 채우지 않음 |
| HL Source (앱 CSV 확장) | strong / log | 앱에서 직접 기록한 세션의 출처·ID를 CSV 왕복에서도 보존하여 중복을 방지 |
| Distance / Seconds | 별도 숫자 | 거리 m, 시간 s. 중량 본세트에 혼합하지 않음 |
| Duration (sec) | 세션별 초 | 반복된 행의 값은 세션당 한 번. 공란은 평균 시간에서 제외 |
| Notes / Workout Notes | 로컬 문자열 | UI에서 일반 텍스트로만 표시. 서버 전송·개발 로그 출력 없음 |

## 직접·간접 세트

카탈로그의 해부학적 분류는 근육 자극량의 정확한 측정이 아닙니다. 복합 동작의 간접 노출에 임의의 0.5 또는 1.0 계수를 곱해 직접 세트에 더하지 않습니다. 하나의 동작이 여러 직접 근육을 가질 수 있어 모든 근육 열의 합은 고유 세트 수와 다를 수 있습니다.

Pelland 2026(온라인 2025)의 메타회귀에서 간접 0.5 환산 모델의 적합도가 높았지만 개인·종목별로 검증된 자극 계수는 아닙니다. 앱 기본 표시는 직접/간접을 분리하여 이 불확실성을 보존합니다.

## 부하 해석

- 톤수: **분류된 외부 중량 본세트**의 입력 kg×반복수. 세트별로 합산하므로 세트 수를 다시 곱하지 않습니다.
- 보조 턱걸이 중량은 보조량. 높을수록 쉬울 수 있어 톤수/e1RM에서 제외하고 그래프에는 최소 보조량을 따로 표시합니다.
- 덤벨의 한 손/양손, 바벨 포함 여부, 머신의 기계적 이점은 자동 보정하지 않습니다. 다른 기구 간 kg 수치를 절대 강도로 비교하지 않습니다.
- Epley 참고 함수: 외부 중량, 3–10회, 명시적 RIR≤2 또는 RPE≥8 조건만 허용합니다. 실제 최대근력이나 근육량이 아니며 기본 UI 차트에는 노출하지 않습니다.
- 알 수 없는 운동은 전체 반복 본세트 수에 포함될 수 있지만 근육별·톤수·e1RM에서 제외합니다.

## 날짜·필터·중복·이상치

주간은 한국 날짜의 월요일 시작입니다. 7일은 오늘을 포함한 최근 7개 날짜이고, 미래 날짜는 통계에서 제외합니다. 연도별 값은 기록된 세션 수이며 실제 운동 전체를 대표하지 않습니다.

같은 Workout #에 서로 다른 시작 시각이 있으면 충돌 행을 거부합니다. 숫자 순서의 완전히 동일한 중복 행은 제외합니다. D 등 특수 표식의 완전히 동일한 반복 행은 실제 여러 서브세트일 수 있어 보존하고 감사에 경고합니다. 원본은 수정하지 않습니다.

헤더/UTF-8/따옴표 오류는 전체 가져오기를 중단합니다. 수치·날짜·열 개수 오류는 해당 행을 거부하고 적용 전 개수를 표시합니다. 상한은 명백한 오류를 막는 소프트웨어 입력 범위이며 생리학적 정상 범위가 아닙니다. CSV 10 MB/50,000행, JSON 백업 50 MB 제한입니다.

## 재현

```bash
npm run analyze -- data/private/<Strong-내보내기.csv>
npm run analyze -- --demo
```

실제 CSV가 없으면 개인 분석은 실행할 수 없습니다. 예시 분석의 JSON과 Markdown에는 합성 예시임을 표시합니다. JSON 백업 schemaVersion은 1이며 알 수 없는 버전·중복 세션 ID·유효하지 않은 수치는 복원 전에 거부합니다.

실제 분석 결과는 reports/private/, 예시 분석 결과는 reports/private/example/에 분리합니다. 예시 명령이 기존 개인 보고서를 덮어쓰지 않습니다. 실제 분석에는 로컬 복원용 app-backup.private.json도 생성하며 공개 배포에 포함하지 않습니다.

## 설계·증량·주간 검토 확장

버전-1 백업과 IndexedDB를 유지하며 다음 선택 필드를 추가합니다. 이전 백업에는 이 필드가 없어도 됩니다.

- profile.customPlans: 환경·구성·빈도·시간·선택 운동·슬롯별 종목 배열. 종목 ID, 성장기 세트, 반복 하한/상한, RIR, 휴식 초를 포함합니다. 중복 종목·잘못된 범위는 거부합니다. 재적응/평가와 압축형의 제한은 적용 후에도 유지합니다.
- profile.recordBindings: 계획 종목 ID와 비교할 원래 Strong 종목명. 사용자가 같은 동작·기구·중량 기준임을 확인해 연결합니다. 과거 기록을 수정하지 않으며 ID와 원래 이름이 모두 같은 최근 28일 본세트만 비교합니다.
- reviews: 검토 주의 시작일, 유지/축소/변경 결정, 사용자 메모, 저장 시각. 메모 저장은 프로그램을 자동 변경하지 않습니다.

주간 계획량은 현재 설정으로 환산한 비교선이며 과거 계획 복원이나 실제 완료율이 아닙니다. 같은 날 두 세션은 운동일 1일·세션 2회로 표시합니다. 기록 없음은 운동하지 않았다는 증거가 아닙니다.
